# ROUTES KNOWLEDGE BASE

## Overview
Flask blueprints live here. Routes are the boundary between static frontends, runtime JSON/SQLite, and core merge rules.
Business meaning is owned by [the Server Rules Index](../docs/SERVER_RULES_INDEX.md);
this file owns route-boundary edit and verification constraints.

## Conventions
- Every new blueprint must be explicitly imported and registered in `app.py`.
- Normal JSON mutation is canonical `core.paths` path + target `file_lock()` + load/merge/`save_atomic()`; atomic replace alone is not RMW locking.
- Class log reads/writes go through `routes.log_repository_provider.get_log_repository()` / `LogRepository`. `routes.api_basic.get_log_repository` remains a compatibility re-export for existing consumers.
- Use `core.log_rules.merge_log_entry_safe` and `log_entry_conflicts_with_base` for merge/conflict behavior.
- Use `core.progress_rules` for watch/progress transitions, `core.watch_progress_writer` for browser/Kollus writes, `core.progress_store` for strict progress caching/locking/saves, and `core.progress_notifications` for milestone hooks. `api_watch` and `api_kollus` must not import each other, and `api_watch` must not import helpers from `api_basic`.
- `api_progress.py` owns `/api/progress` and `/api/progress/patch`. Preserve date/single-SID/batch-SID response shapes, numeric SID compatibility, ghost 403, merge-source semantics, compact atomic persistence, structured `progress_lock_timeout`/`retryable:true` 409, and post-save milestone delivery; keep these HTTP routes out of `api_basic.py`.
- `api_logs.py` owns `/api/logs`, `/api/logs/entry`, `/api/logs/unarchived-summary`, `/api/logs/patch`, `/api/logs/patch-batch`, and `/api/homework-books`. Preserve response shapes, batch-SID/export filtering, dual-store partial-success semantics, ghost rejection, placeholder repair, and validation-before-write; keep these HTTP routes out of `api_basic.py`.
- `api_materials.py` owns `/api/materials` and `/api/mat-assign`. Preserve the coordinated three-store revision, GET-only materials contract, `If-Match` 428/409 behavior, last-good degraded reads, and 503 write blocking; keep these HTTP routes out of `api_basic.py`. Bootstrap may call the path-injected `material_state_provider` with its own fixture/runtime paths.
- Attendance, makeup sheet sync, and the offline sync script must use `routes.absence_assignment_cleanup.absence_write_scope` plus `commit_new_absences_locked`; never import cleanup helpers from another blueprint. Preserve date/SID scope, carryover-before-clear ordering, the 8-second update/progress locks, normal response/revision shapes, startup recovery, and post-commit-only schedule notifications.
- Arrival-time routes use `/api/arrive-time` and `/api/arrive-time/patch`; `/api/arrive-time/missing-leave-summary` is their read-only 2026-08-29+ effective-roster arrival-versus-log warning projection. The incomplete 2026-08-28 historical traces stay outside this baseline. A row must still belong to that exact date's current regular/extra/active-scheduled-makeup roster, so an old arrival trace left after moving or cancelling a makeup cannot warn. It also excludes explicit absences, today/future and the actively selected date, and returns only date/SID/arrival summary fields. The retired prefixless `/arrive-time*` aliases must stay unavailable.
- `/api/attendance` and `/api/contact` are GET-only. Writes must use their single-student `/patch` endpoints; retired bulk POST handlers must stay unavailable.
- General date-indexed reads/writes use `core.date_rules.is_iso_date_key` or `parse_iso_date_key`. A shape-valid impossible date such as `2026-02-30` must return 400 before opening a repository, taking a mutation lock, invoking an assignment hook, sending a notification, or writing JSON/SQLite. Preserve the D-04 whole-map `/api/absent` 500/no-write exception until the user explicitly changes that decision.
- `api_schedule_overrides.py` owns `/api/extra-attend` GET/PATCH and `/api/weekend-slots` GET/POST; keep both HTTP routes out of `api_basic.py`. Weekend POST must validate the entire patch before locking or invoking hooks: malformed/non-object/empty bodies and invalid dates return 400, ghost returns 403, and unknown roster SID returns 404 with byte-identical stores and no reconcile/notification. Preserve successful 204 and student-scoped merge. An explicit today extra PATCH always replays the idempotent initializer, including a no-op identical retry after the source store committed but a previous hook failed; keep its successful body and `changedDates` meaning unchanged. Extra attendance uses only `/api/extra-attend`; the old `/api/extra`, `/api/extra_attend`, and `/api/extra-attend/all` names never existed on the live server and must not be revived. App composition injects the public automatic-assignment callbacks so this blueprint never imports `api_basic` private helpers.
- `api_updates.py` owns `/api/updates`, `/api/updates/patch`, and `/api/updates/self-study`; keep all three HTTP routes out of `api_basic.py`. App composition injects the public compatibility hooks, while `student_auto_assignment_service.py` owns automatic/self-study runtime reads, the injected absence coordinator barrier, locks, and saves and the route retains HTTP validation/response behavior. PATCH requires an object body and exact JSON boolean `remove`; non-object bodies and string/number/null removal values return 400 without loading or writing the store. PATCH and self-study both require a real canonical date before the store or reconciliation hook. Reject a future named `source:auto` from the final assignment after merging under the updates lock, not from the incoming fragment, while allowing explicit removal or reclassification away from `auto`. Use `core.update_assignment_store` for every updates read/save; per [`RULE-VIDEO-001`](../docs/SERVER_RULES_INDEX.md#rule-video-001), unreadable/non-object stores return 503 and remain byte-identical, while only a missing file projects an empty map. Real-today initialization and self-study reconcile must enter the barrier before re-reading authoritative absences and taking the updates lock; never trust a caller snapshot loaded before that barrier.
- Updates PATCH/self-study lock contention returns structured `updates_lock_timeout` with `retryable:true`; this is the only updates 409 class the admin may retry automatically. Revision/base conflicts remain fail-closed under [the canonical admin save-conflict contract](../docs/PROJECT_FUNCTIONS_AND_LOGIC.md#admin-latency-contract).
- `api_student_bootstrap.py` owns `GET /api/student/bootstrap`, request validation, public active-SID binding, academy classification, public recursive link stripping/latest-watch projection, and no-cache response composition. `student_bootstrap_projection.py` owns the Flask-free aggregate payload. App composition injects one explicit dependency bundle from `api_basic.py`; do not restore the endpoint or duplicate payload assembly there.
- Keep date/slot/self-study/absence interpretation in `core.student_schedule_rules`, current-course completion/blocking/review response logic in `core.student_video_projection`, and assignment list selection/rebase transforms in `core.student_video_assignment_rules`. `student_auto_assignment_service.py` alone composes those rules with injected runtime stores and locks; `api_basic.py` may build dependencies and expose compatibility wrappers but must not duplicate service behavior.
- Bare `GET /api/updates` is a legacy mutating read only for the real current KST date: it may create today's missing assignment or rebase today's stale curriculum MIDs. `GET /api/updates?readOnly=1`, historical/future loads, and future schedule events must remain storage-only. Student bootstrap may auto-assign only for a non-public request for real today; public or non-today bootstrap reads storage without creating an assignment.
- `/api/updates` is GET-only. Assignment writes must use `/api/updates/patch` or the validated `/api/updates/self-study` flow; the retired multi-date/student base POST must stay unavailable.
- Automatic video targets are scheduled or extra-attendance students who are not absent/done, plus the separate self-study mode. The configured count is 1-6 (default 3, A:Ble default 1); adjacent active class slots double the date-specific effective count after weekend overrides and slot absences. Initial candidates stay inside the exact current curriculum/sub-curriculum and exclude finished `done`/`skip` history.
- The approved shared/UI count cap is 6. Backend coercion, roster field updates, and new automatic date snapshots all use 1-6; existing dated snapshots and stored roster rows are not bulk-rewritten or resized.
- Preserve assignment source semantics: automatic snapshots may exist only for today or past dates and are immutable after creation except for an explicit current-day curriculum rebase. Never create, resize, or retain a future named `source: "auto"` snapshot; real-today initialization removes only that future residue. Progress/watch, ordinary schedule/consecutive-slot, count writes, and all-done/all-skip log saves must never advance, shrink, remove, or refill an existing auto snapshot. A newly registered absence transaction is the explicit exception: it removes that date/SID assignment, and cancellation does not restore it. Count writes persist only the student setting used by the next real-date initialization; explicit future `manual`, `selfStudy`, and unknown legacy entries remain protected.
- Bootstrap `videos` contains unfinished assigned catalog rows plus completed rows from today's named `source: "auto"` snapshot; retained completed rows carry `todayAutoAssignmentStatus: "done"`. Historical, skipped, and self-study completions stay out of that playlist. `reviewVideos` contains sanitized, current-curriculum, `done` rows through the requested date, excluding every still-visible assignment; it never exposes raw progress/watch/event-date data. Absent, archived, ghost, course-blocked, or malformed flows return an empty review array. Run `verify_student_bootstrap_routes.py` for literal route/projection oracles and byte/SHA-256 invariance.
- `POST /api/updates/self-study` revalidates self-study/absence/archive state and only accepts current-curriculum videos completed strictly before the target date. It is not the student review button's persistence endpoint.
- `POST /api/videos` is a locked full-catalog save in normal mode. It must return 409 before writing when an existing stable row ID is removed or its URL-derived MID changes. Same-MID signed URL/metadata edits and new rows are allowed. Do not add a body/query bypass; correction drafts stay browser-local and live apply is an offline maintenance script with Waitress stopped and a verified backup.
- `api_videos.py` owns both `/api/videos` methods and their route-local normalization/identity guard. Keep the catalog HTTP boundary out of `api_basic.py`; automatic assignment and bootstrap may continue loading `VID_PATH` directly for their own projections.
- `/api/get-url` must validate academy access, session SID, known SID, and known MID. Browser watch writes share those academy/SID/ghost gates. Configure `KOLLUS_CALLBACK_SECRET` for exposed LMS callbacks; callbacks cannot use the browser's academy-only gate because Kollus must reach them.
- `/api/watch/latest`, browser `/api/watch`, and compatibility `/api/watch-status` share canonical real-date validation. Invalid dates must leave both `watch.json` and `progress.json` byte-identical; do not weaken academy/public-SID/ghost gates or the compatibility response shapes.
- Keep `/api/watch-status` only as a temporary compatibility endpoint for the student app being developed on another computer. The current web student must use `/api/watch`; do not add new `/api/watch-status` consumers, and remove it only after the external app migrates and is merged.
- Preserve endpoint URLs, payload keys, response shapes, and cache behavior unless a dedicated migration is part of the task.
- /api/students, /api/materials, and base /api/logs are GET-only. Keep student mutations on the locked add/field-update/delete routes and class-log mutations on /api/logs/patch or /api/logs/patch-batch; do not restore whole-collection POST handlers.
- [`RULE-IDENTITY-001`](../docs/SERVER_RULES_INDEX.md#rule-identity-001) owns student/person meaning. When person identity is configured, add, clone, shared-profile update, and retirement must delegate to `core.person_identity_store` so `persons.json` and `students.json` commit through one journal. Clone reuses the source `personId`; ordinary add creates a person. Keep shared profile fields separate from SID-specific fields, reject attempts to mutate `id` or `personId`, and return 503 on configured partial/unreadable/recovery-required state instead of taking the legacy roster-only path.
- `api_students.py` owns `/api/students`, `/api/add-student`, `/api/update`, and `DELETE /api/students/<sid>`; keep these routes out of `api_basic.py`. Preserve A:Ble count defaults through `core.student_auto_assignment_rules`, schedule notifications, and the existing post-save automatic-assignment effects. App composition injects public callbacks from `api_basic`; the student blueprint must not import its private helpers.
- `/api/update` accepts `whiteReviewPending` only as an exact JSON boolean. It is an SID-only `students.json` field and must use the same identity journal or legacy roster lock without schedule, assignment, notification, log, attendance, or progress side effects.
- /api/fs/page-folders GET/POST is retired. Do not restore the HTTP surface; preserve PAGE_FOLDERS_PATH and existing local data unless a separate internal-store retirement is explicitly approved.
- File rename/move/delete/upload use the file-tree lock first, then material_state locks. Korean safe names must remain valid; prefix rewrites are path-segment aware across materials, assignment URL/relative/DIR tokens, and pageFolders. Delete stages content before commit, and a pre-journal failure restores the filesystem.
- `/api/mat-assign` GET carries the whole material-state revision and POST requires `If-Match`; a stale writer returns 409 without mutation. Student bootstrap and `/api/materials` read the same coordinated snapshot. Recovery-required material/file writes return 503 while unrelated routes remain available.
- `api_school_calendar.py` owns `/api/school-calendar`. GET returns the document with `X-School-Calendar-Revision` and ETag. POST requires the matching revision in `If-Match`; missing/invalid revisions return 428, stale revisions return 409, and unreadable/locked stores return 503 without replacing the file. Preserve the successful response body shape for existing page consumers and keep this route out of `api_basic.py`.
- External administrator API Basic auth must preserve each student/integration route's existing gate and status contract. In particular, `/api/get-url` remains academy/SID/MID gated and Kollus callbacks remain callback-secret gated.
- `GET /api/logs`, `GET /api/logs/entry`, `GET /api/updates`, and today's student bootstrap can touch runtime state; treat "read-only" smoke checks carefully.
- Assistant-note GET/list can enable WAL, create/migrate schema, and backfill `updated_by`; exclude it from filesystem-pure smoke checks.
- Assistant notes accept same-origin `/admin` and `/dh1130` for full CRUD. Same-origin `/students` and `/all.html` may only GET/list and POST/create; PATCH/DELETE stay forbidden there, and student pages remain forbidden.
- Student bootstrap returns `assignedTests` as a top-level array. `progress[date][sid].tests` is authoritative; log `assignedTests` is metadata/fallback.
- Legacy `/api/submit-test`, `/api/ocr-test-sheet*`, and `/student-test/<sid>` remain retired. The separately registered, default-off `/api/student-test-ocr/*` blueprint must keep `/api/tests` GET-only and preserve its academy/session gates, one-time capture tokens, administrator Basic auth, no-store crop responses, and answer-key non-disclosure.
- The OCR academy gate may accept only `is_verified_isolated_server_root()` for loopback QA. Never generalize this into localhost/loopback production access or an environment-only bypass.
- No known private cross-blueprint import remains. Public `routes.api_basic.get_log_repository` consumers remain supported by the compatibility re-export, while new code uses `routes.log_repository_provider`; `api_fs` must use `core.announcement_image_access`, and `api_tests` must use `core.storage.file_lock` plus `core.test_answer_links`. Do not reintroduce the former watch/Kollus, makeup/attendance, test lock/answer-link, or file/announcement private seams.
- [`RULE-TEST-001`](../docs/SERVER_RULES_INDEX.md#rule-test-001) splits catalog writes by scope. A single test definition uses revisioned `PATCH /api/tests-config/test` and explicit `clearFields`; global rules, bulk changes, and deletion use revisioned `POST /api/tests-config`. Both require the preceding GET's `X-Tests-Config-Revision`, reject missing/stale revisions with 428/409 before writing, and preserve `sourceFiles`, source IDs, unknown fields, answer rounds, and all untouched tests. Never POST a network-stripped GET representation.
- Quick-printer preview/export stays administrator-only and no-store. Preserve current-subject `assigned`, selected SID order, mapping-wide failure, BOM/filename/CSV shape, and exact JSON boolean reprint input. Preview never records history; export must persist every returned row's generated-history transaction before exposing CSV, and any history failure returns no CSV.

## Runtime Data
- Runtime files are real local data; use [`RULE-DATA-001`](../docs/SERVER_RULES_INDEX.md#rule-data-001) and the canonical data-source table instead of maintaining another complete list here. In particular, `persons.json`, `students.json`, the person-identity journal, `tests-config.json`, `app.sqlite`, and sidecars are operational state.
- Before migrations, repair jobs, or bulk rewrites, run `python scripts/backup_runtime_data.py`.
- Prefer PATCH-style route updates over full-map replacement.
- Log snapshot/partial-success behavior follows `RULE-LOG-001`: a SQLite conflict never writes the JSON fallback; a successful complete snapshot owns explicit field absence. Newly registered absence cleanup still uses its separate rollback-first journal transaction. Verify other dates/SIDs survive, `assigned` becomes `interrupted`, carryover is collected before mutation, every injected failure restores all stores, and recovery-required state returns 503/fails startup rather than accepting another related write.

## Anti-Patterns
- Do not open-code SQLite plus `logs.json` merge behavior in route handlers.
- Do not let automatic watch progress overwrite manual white, skip, or explicit clear markers.
- Do not treat `interrupted` as eligible student review membership merely because the pure resolver can project it; current chooser/self-study policy is done-only.
- Do not add `/api/updates/review` or `/api/updates/training-pack` calls: no such video-assignment routes exist. Student review registration is local-only.
- Do not make admin modal hydration call the mutating `/api/updates` GET.
- Do not resurrect stale cleared test assignments from log metadata.
- Do not expose Drive answer links when network gating says to strip or restrict them.
- Do not reconnect the separate non-student OCR cache/lab to student routes, test history, progress, or logs. A future student submission flow must be rebuilt and reviewed as a new feature.
- Do not expose assistant notes through student bootstrap, test records, CSV/print exports, or browser storage.
- Do not copy legacy `api_todaymeta.py` or `api_auth.py` open-coded JSON patterns into new routes.
