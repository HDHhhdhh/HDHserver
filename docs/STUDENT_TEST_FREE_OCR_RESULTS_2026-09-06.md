## 결과

무료 경로를 유지했다. 같은 사진·같은 가중치에서 **주관식은 원본 crop이 기존 이진화/차영상보다 유리**했다. 객관식에는 반대 결과가 나와 전처리를 유형별로 분리했다. 추가 GPU 학습은 실행하지 않았으며 공개 데이터 준비와 실행 패키지 검증까지 완료했다. 운영은 OFF / NO_GO다.

| 수식 모델 | 원본 crop | 기존 보정 crop | 테두리 제거·ink ROI 후보 |
|---|---:|---:|---:|

분모는 동일한 기존 사진의 숫자 56·분수 1·루트 3개다. 측정값은 **숫자값 동치율**이며, 실제 20문항 촬영 성공률·자동 확정률·독립 holdout 정확도가 아니다. 이 진단으로 정책 임계값을 낮추거나 99% 정확도를 주장하지 않는다. 수식은 단일 primary 추론을 비교했고 보조 엔진 합의·재촬영·큐 대기시간은 측정하지 않았다.

전처리 3종 × 수식 모델 3개 × 60문항 = 540회와, 객관식 모델 2개 × 전처리 3종 × 40문항을 실행했다. 별도 검토 후 입력/코드/tokenizer 해시 및 생성 상한 판정을 보강해 전체 비교를 한 번 더 실행했다. 최종 근거는 `generated/free_ocr_20260906/ablation_verified/`다. 초기 `ablation/`의 생성 상한 집계는 최종 증거로 쓰지 않는다.

- `report.json` SHA-256: `67f2d6f7dd32022688b5959e20f9c1340364cb59a0e3fe01ee449378b79e039a`
- `predictions.jsonl` SHA-256: `facd6a24bc7659d6dcc8ecbf4463c5f760249fbaaf0de92587136a90709bdfac`
- 모든 모델은 동일한 deterministic 64-token 생성 상한을 사용했다. 강제 EOS라도 상한에 도달하면 실패로 계산했다. base의 원본/기존/후보 상한 도달은 2/12/4건, 두 반환 모델은 각 조건 0건이다.

## 반영·기각

`student_test_ocr_job_runner`는 카탈로그의 `answerModes`만으로 crop을 선택한다.

- `choice_number`: 기존 `recognitionImagePath` 유지.
- `answer_value`: 원본 `imagePath` 사용. 문항 재촬영의 원본 입력과도 일관된다.

이 변경은 feature-OFF의 코드에 반영했으며 운영 서버를 재시작하지 않았다. readiness의 파일 해시에 job runner를 포함해, 이후 crop 선택 코드가 바뀌면 옛 출시 근거를 재사용할 수 없게 했다.

테두리 제거 후보는 실험 코드와 음성 사례로만 보존한다. 객관식 v3에서 원본 8/38, 기존 보정 22/38, 후보 12/38이었다. 특히 후보는 자동 수락 29건 중 19건을 잘못 수락했다. AI Hub v4도 기존 보정 27/38에서 후보 15/38로 낮아졌다. **깔끔하게 보이는 이미지를 더 좋은 OCR 입력이라고 가정하지 않는다.** 기본 객관식 모델은 v3를 유지한다.

기존 상위 best4000은 로컬에 없다. 외부 반환 파일은 두 프로필 모두 latest5000이고, best4000의 경로와 회수 지시는 GPU 프롬프트에 포함했다. 없는 모델은 이번 비교에 포함했다고 표시하지 않는다.

## 공개 데이터 준비

원본 grade crop과 기존 전체 프로필은 보존하고 별도 폴더에 다음 파생 입력을 만들었다. 5,498개 이미지 참조의 PNG 무결성과 이미지/라벨/행 개수·해시를 확인했다. 두 프로필은 데이터가 겹치므로 이 합계를 독립 이미지나 독립 표본 수로 해석하지 않는다.

| 프로필 | 짧은 답안 Training | Training writer hash | 작성자 제외 Validation | Validation writer hash |
|---|---:|---:|---:|---:|
| 중3+고1 | 919 | 73 | 1,459 | 3 |
| 중3+고1+고2+고3 | 1,647 | 121 | 1,473 | 6 |

선별은 `numeric_answer_value`가 지원하는 라벨 문법을 사용하며 주관식 `1~5`도 포함한다. 이것은 데이터 라벨을 골라 학습 후보를 만드는 과정이지, 운영에서 정답을 보고 인식값을 고르는 과정이 아니다. 검증 작성자 제외는 작은 focused train이 아니라 기존 전체 Training provenance를 기준으로 했다.

검증의 학년별 구성은 중3 1,332/고1 127/고2 14/고3 0이다. 따라서 crop 수가 많아 보여도 고3 성능이나 다양한 새 필체 성능을 주장할 수 없다. writer hash는 grade-scoped 공급 식별자이며 누락 시 파일 기반 식별자가 사용되는 한계가 있다.

## 외부 GPU 인수인계

현재 호스트는 CPU-only이고 다른 컴퓨터의 CUDA 작업을 실행할 연결이 없으므로 **실제 추가 학습은 미실행**이다. 다음 두 파일을 GPU 컴퓨터로 전달하면 된다.

- 패키지: `generated/free_ocr_20260906/student_test_free_ocr_gpu_20260906_verified.zip`
- [One-shot 실행 지시](STUDENT_TEST_FREE_OCR_GPU_PROMPT.md) — Drive 링크와 ZIP 검증값을 포함한다. 패키지 안 `GPU_PROMPT.md`는 링크 추가 전 오프라인 지시본이다.

최종 ZIP: 55,898,650 bytes, 5,526 files, SHA-256 `3ae04d5bedd36bf380699005a9970f1f581a59ab67013e18bfad4e68c0fd8402`. ZIP CRC/파일 수와 manifest 파일별 SHA-256을 확인했다. 학생 촬영 사진, 운영 DB, 기존 가중치는 포함하지 않았다. 초기 suffix 없는 패키지는 감사용으로 남겼으며 전달 대상은 `_verified.zip`이다.

실험은 full/focused × 두 프로필, 동일 base·seed·batch4/accum2·1,000 microbatch iteration씩 4회다. 이것은 데이터 선택 효과를 비교하는 제한된 파일럿이며 최종 학습량 확정이 아니다. 원격 full Training의 실제 이미지/annotation 서명과 작성자 제외 provenance가 패키지와 다르면 학습을 차단한다. best checkpoint가 없으면 latest로 대체하지 않는다.

최종 패키지 자체 코드에서 `--train` 없이 네 설정 생성과 실제 원천 해시 검증을 완료했다. 로컬 검증 기록은 `generated/free_ocr_20260906/local_config_verified/EXPERIMENT_PLAN.json`이다. 네 설정은 **최종 GPU 경로에서 다시 생성**해야 한다.

### 다음 사이클이 반복하지 말아야 할 실패

`re0-memo`로 다음 검증 기준을 남긴다.

1. **모든 인식기에 같은 전처리 강제:** 이번에 객관식과 수식의 유불리가 반대였다. 문항 유형·모델별로 원본 대조군을 유지하고, 외관보다 인식값·오수락으로 채택한다.
2. **폴더/이름만으로 동일 데이터라고 판단:** 원격 기존 데이터가 달라지면 작성자 분리 근거도 무너진다. 입력 내용과 배제 provenance를 전달 패키지에 묶고 차이가 나면 새 실험으로 취급한다.
3. **반환 EOS를 정상 종료로 간주:** decoder가 길이 상한에서 EOS를 강제할 수 있다. 토큰 수 상한에 닿으면 불완전 출력으로 세며 분모에서 빼지 않는다.
4. **표본 수를 필체 다양성으로 대체:** 1,473 crop이어도 writer hash가 6개이고 고3은 없다. 다음 GPU 보고서에 학년/작성자별 표본과 누락을 필수로 둔다.

남은 것은 외부 GPU의 실제 실험·best 회수, 그리고 이후 새 v4 촬영의 calibration/독립 검증이다. 7일 삭제 정기 실행·재시작 복구·실제 20문항 지연시간 등 운영 준비 항목은 이전 검토 기록처럼 여전히 별도이며 완료로 바꾸지 않았다.
