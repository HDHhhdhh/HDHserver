결과와 범위
프로젝트 구조·문서·주요 서버 경계·11개 HTML shell과 주요 페이지 기능을 조사했다.
확인된 데이터 유실 및 비동기 UI 경합 경로를 우선 수정하고, 비용이 큰 목록/학생 투영을 최적화했다.
현재 변경분의 전체 기본 회귀 검사와 문법 검사는 통과했다.
이 보고서는 1차 검토와 수정 결과다. 모든 화면의 모든 버튼에 대한 실제 지연 측정 완료, 모든 오류 후보 수정 완료, 운영 배포 완료를 뜻하지 않는다.

1. 구조와 규칙 문서 정합성

실제 구조
- app.py: 앱 생성, guard 순서, public service 주입, Blueprint 등록.
- routes/: HTTP 인증·요청 검증·transport. api_basic.py에는 일부 서비스 조립/호환 경계가 남아 있다.
- core/: 순수 규칙, strict 저장소, 잠금·트랜잭션·복구, projection.
- static/: HTML shell, CSS, native ES modules와 학생 classic-script controller.
- scripts/: bespoke 안전 검사, 격리 서버 manager, 운영 도구.
- docs/: SERVER_RULES_INDEX가 규칙 소유권의 시작점, PROJECT_FUNCTIONS_AND_LOGIC이 의미 정본, CODE_FLOW_MAP이 구현 경로, LOGIC_DECISION_LEDGER가 승인 결정.
- JSON/SQLite 및 instance/files 등은 별도 runtime/local state다. 소스와 Git 등록 대상으로 합치지 않는다.
- 프런트엔드 패키지 runner 또는 새 프레임워크를 도입하지 않았다.

읽기 전용 정적 조사
- 정본 5개 + AGENTS 14개: 로컬 링크·앵커 130개, 파일 참조 1,181개 대조.
- Python 150개 AST, route/method 선언 170개: 조사한 소유권 중복 및 지정된 retired surface 복원 없음.
- 루트 HTML 11개, 로컬 script/CSS 참조 44개, 상대 JS import 236개: 대상 누락 없음.
- 이 수치는 조사 범위이며 운영 활성 설정·외부 소비자·외부 링크까지 검증했다는 뜻은 아니다.

수정한 문서
- 오늘 source:auto 완료 영상의 표시·복습 예외를 현재 승인된 구현과 맞춤.
- 전체학생 페이지의 실제 lazy 통합 팝업과 dormant 미니 편집기를 구분.
- quick-printer SQL 열을 assignment_date로 정정.
- OCR worker 고정 개수 설명을 manager의 실제 복사 목록과 맞춤. OCR 활성화 없음.
- 역사적 D-01 네트워크 제한을 현재 정책으로 읽지 않도록 표현 정리.
- quick-printer API 옵션 생략값과 팝업 최초 체크 상태를 구분.
- configured identity strict 조회, attendance/contact 쓰기 실패 계약, 팝업 경합 방어, 파일 관리 새로고침/저장 규칙과 새 회귀 검사를 기록.
- QA Basic 인증은 격리 프로세스 환경에만 적용하고 부모 환경을 복원하는 runbook 추가.

남은 문서 개선
루트 AGENTS.md는 32,645 bytes로 32 KiB 제한까지 123 bytes만 남는다. 필수 안전 규칙을 유지하며 상세 반복을 기존 scoped owner 링크로 줄일 별도 소규모 작업을 권한다.
학교 일정 등 과거 rollout 상태는 운영 재시작 기록만으로 현재 실행 코드와 일치한다고 확정하지 않았다.
이 작업에서 운영 rollout 상태를 임의로 완료 처리하지 않았다.

2. 수정 완료한 오류 경로

A. configured identity
core/paths.py, routes/api_students.py

- 임시 root/route 검증에서 원본 바이트와 누락 상태 보존 확인.

B. 출결·연락 PATCH
routes/api_attend.py

- 읽기용 legacy fallback 계약은 별도로 보존.

C. 격리 서버 manager
scripts/manage_isolated_design_server.ps1
- 리스너 조회 실패를 “포트가 비어 있음”으로 해석하지 않도록 변경.

- AccessDenied fixture에서 Status/Start/Restart/Stop이 launch·kill·receipt 삭제로 진행하지 않음을 확인.
- 정상적인 리스너 없음 상태는 별도 검사.
- 동시 Start의 더 넓은 프로세스 경합까지 해결했다고 주장하지 않는다.

D. 파일 관리
static/js/file-manage.js
- 독립적인 트리·명단·배정 GET을 동시에 시작.

- 저장 대상 SID·자료를 await 전에 고정. 저장 중 새로 추가한 draft는 보존.
- duplicate 실행 차단, 반복 렌더의 박스 선택 listener를 한 번만 설치.
- 전체 취소는 정상 준비 상태에서 기존 의도된 계약을 유지.

E. 관리자/전체학생 통합 팝업

3. 남은 잠재 오류 목록

아래는 운영 발생 기록이 아니라 소스에서 확인된 후보다. 새 결정적 실패 주입 및 운영 영향 검증 여부를 따로 표시한다.

P1 / legacy 계정 저장 경합
근거: routes/api_auth.py의 로그인/SID refresh/credential 변경 전체-map read-modify-write와 고정 .tmp; core/student_app_auth_store.py는 같은 저장소에 lock 사용.
조건: legacy writer가 읽은 뒤 다른 writer가 비밀번호/계정을 변경하면 오래된 map이 최신 값을 지울 수 있음.
후속: 모든 writer가 동일 canonical lock 안에서 read→검증→merge→save_atomic 수행. 저장 함수만 잠그면 stale map 문제가 남음.
새 결정적 두-thread 재현: 미완료. 이 작업에서 계정/운영 credential 변경 없음.

P1 / watch 손상 저장소 fallback
근거: core/watch_progress_writer.py의 비-object 빈 맵 정규화 및 shared storage load의 일부 읽기 fallback.
조건: 손상된 저장소가 정상 빈 상태로 해석되어 후속 쓰기에 덮일 가능성.
후속: 파일 부재와 손상을 구분하는 strict watch read + no-write fixture. 기존 manual white/skip/interrupted, millisecond timestamp, Kollus callback/auth 계약 유지.
새 실패 주입: 미완료. 이 작업에서는 watch 파일 형식/운영 데이터 수리 없음.

P2 / batch 로그 mirror 실패 응답
근거: core/log_repository.py batch SQLite commit 후 JSON mirror save 예외와 routes/api_logs.py 응답.
조건: SQLite에는 저장됐는데 JSON 실패로 500이 전달될 가능성. 단건의 부분 성공 계약과 차이.
후속: commit 뒤 mirror failure를 명시한 결과, reload/restart/clear/unknown 필드 검증.
새 mirror 실패 주입: 미완료.

P2 / invalid date 검증 순서와 bootstrap 날짜
근거: app.py 전역 absence barrier가 route 검증 전에 실행; bootstrap의 date.fromisoformat.
조건: 잘못된 날짜도 먼저 barrier/복구 경계 진입, compact/week date 허용 가능성.
후속: 인증 순서 유지하며 canonical date 판정을 관련 barrier 앞에 배치, middleware 포함한 임시 fixture로 lock/hook/write 호출 0 확인.
D-04 whole-map absent의 승인된 500+무쓰기 제한은 별도이며 자동 수정 대상 아님.

P2 / tests-config 전체 POST metadata 보존
근거: core/test_config_safety.py의 incoming 기반 merge와 선택적 metadata 복원.
조건: sourceId/unknown/category/top-level metadata가 payload에서 빠지면 사라질 가능성.
후속: 기존 ID 기반 merge 및 명시적 삭제/clear-field 의미 보존. 428/409·answer metadata·generated map·PATCH 회귀.
정상 UI가 현재 모든 값을 보내는 흐름과 API 보존 계약 갭을 구분한다.

P2 / 관리자 공지 발행 경합
근거: static/js/admin/features/announcements.js의 발행 잠금 부재와 성공 뒤 현재 draft 초기화.
조건: 중복 POST, 이전 성공이 새 draft 제거, POST 성공+목록 GET 실패가 등록 실패로 보임.
후속: 발행 command/session 고정, 중앙 in-flight 제어, 발행과 후속 refresh 결과 구분.
새 지연 응답 VM/브라우저 재현: 미완료.

P2 / 학생 공지 답장·설문 경합
근거: static/js/student.js의 await 뒤 active/익명/폼 상태 재사용.
조건: A 전송 중 B를 열면 A 응답이 B draft/상태를 바꿀 가능성.
후속: 대상·입력·익명·session 고정, 원래 공지 상태 갱신, 같은 열린 session에만 화면 피드백.
서버 전송 대상 변경 여부까지 확정하지 않았다.

4. 리팩토링과 반응속도 개선

원칙
큰 모듈을 재작성하지 않고 기존 owner 경계 안에서 실패 은폐, 중복 listener, 오래된 응답의 DOM 적용, 불필요한 전체 SID/목록 처리를 줄였다.
static/js/video-manage.js의 생성 citation 주석 잔재를 제거했다.
호환 alias, fallback router, dormant 기능, 직접 URL로 제공될 수 있는 asset은 소비자 증거 없이 삭제하지 않았다.
새 프레임워크·endpoint/payload 변경·runtime migration은 없다.

성능 수정
- 학생 bootstrap의 응답용 progress/watch 이력을 요청 SID/숫자 별칭으로 좁힘.
  real-today 전체학생 자동 배정 서비스는 기존 범위를 유지.
- 영상 목록: 빈 검색에서 검색키 정규화 생략, duplicate ID의 첫 원본 인덱스를 보존하는 Map.
- 시험 목록: 빈 검색에서 검색키 조합 생략. 출력 순서/이름/필터 의미 유지.
- 파일 관리: 독립 GET 3개 동시 시작, listener 누적 제거.
- 팝업: loading/저장 상태를 분명히 하고 불필요한 중복 요청·늦은 재렌더 방지.

측정 해석
- 위 값은 운영 HTTP/클릭→화면 완료 지연이 아니다.
- bootstrap: SID 축소+aggregation 포함, JSON I/O·다른 projection·HTTP 제외. 입력 12,386,884 bytes. 출력 동등/입력 hash 불변 확인.
- 영상: 실제 drawVid를 synthetic DOM에서 실행, 3,000행 HTML 동등 확인. 브라우저 layout/paint 제외.
- 시험: 실제 pure catalog/helper 실행, 결과 동등 확인. network/DOM/layout/paint 제외.
- 파일 병렬 조회 및 반복 20회 listener 1개는 behavior VM으로 검증. 실제 네트워크 지연 개선 수치를 별도로 주장하지 않는다.
- 독립 조사 thread의 메모리 비교안 수치와 최종 패치의 Hub 측정 수치는 혼합하지 않았다.

5. 추가 개선 제안과 우선순위

1순위: runtime 손상/경합 방어
legacy auth와 watch strict store를 먼저 결정적 fixture로 재현한 뒤 각 canonical 저장 경계로 수정.
순수 검사와 isolated fixture로 먼저 완료하고 운영 데이터 repair와 분리한다.

2순위: modal 저장 command와 화면 session 분리
공지·학생 공지·날짜 출결에 이번 epoch/owner pattern을 적용.
통합 로그/진도/이월/시험의 여러 API 저장은 partial-success 의미를 명시하고 향후 서버 command 경계로 묶을지 검토.
묶는 변경은 기존 쓰기 순서·base 충돌·revision·clear-field·unknown 보존 oracle이 있어야 한다.

3순위: 실제 화면 지연 기준
각 페이지에 첫 표 표시, popup loading 표시, 내용 ready, 저장 버튼 feedback, 서버 commit 확인, close 완료를 따로 측정.
대표 데이터 크기와 동일한 반복/브라우저/네트워크 조건으로 p50/p95와 요청 수를 남긴다.
합성 helper 개선 수치를 사용자 체감 지연으로 환산하지 않는다.

4순위: 중복 조회 합치기
today refresh의 진행 중 요청 공유를 날짜·force 의미별로 검토.
popup cache의 pending promise는 완료 전까지 공유하고 TTL은 완료 결과에만 적용하는 방안 검토.
실패 cache 제거·저장 무효화·날짜 전환·ready 상태 회귀가 선행 조건.

5순위: 구조와 검사 정리
core.paths 경로 선언과 store 초기화를 분리하여 import의 파일 생성 부작용 축소.
app import 없는 링크/asset/route owner 검사 편입.
api_tests historical projection, makeup payload 규칙, bootstrap assigned-test 표현을 책임별 pure module로 점진 분리.
루트 AGENTS 반복을 child owner 참조로 축소. 현재 안전 규칙을 제거할 근거로 사용하지 않는다.
