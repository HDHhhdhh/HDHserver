## 5. 이번 감사에서 새로 발견하고 해결한 문제

### 5.1 시청 `updatedAt` 32비트 절단

학생 JS가 `Date.now()`으로 만든 13자리 밀리초를 `updatedAt | 0`으로 변환했다. JavaScript 비트 연산은 signed 32-bit로 강제하므로 10자리 안팎의 무관한 값이 서버에 저장됐다. 이전 세션에서 일부 값이 “2037년 미래 시각”처럼 보인 것은 이 값을 epoch seconds로 오해한 진단이었고, 실제 원인은 단위가 아니라 비트 절단이었다.

수정:

- 현재 학생 JS와 legacy 학생 사본에서 `updatedAt` 비트 연산 제거
- 2000-01-01 이후 epoch milliseconds만 유효하게 인정
- backend도 10자리 seconds/32-bit 값을 0으로 정규화
- 다음 정상 watch 저장에서 서버 밀리초로 자연 교정
- 기존 `watch.json` 일괄 rewrite는 하지 않음
- source regression과 Python unit 추가

영향: 기존 위치·길이·완료·수동 진도는 보존된다. 유효하지 않은 시각만 해당 학생/영상의 다음 저장 때 복구된다.

### 5.2 공개 HTTP 미강제

감사 당시 `http://5a-math.com`과 `http://app.5a-math.com`이 200을 반환했다. Flask에 공개 host allowlist 기반 308 전환을 추가했다.

보안 계약:

- 공개 두 host만 HTTPS로 전환
- 경로·쿼리 보존
- 학원 LAN HTTP 유지
- Cloudflare Tunnel에서는 `CF-Visitor.scheme`을 우선하고, 일반 프록시는 `X-Forwarded-Proto`로 fallback
- forwarded HTTPS는 신뢰 프록시에서만 인정
- 외부 클라이언트가 `CF-Visitor` 또는 `X-Forwarded-Proto`를 위조해 우회할 수 없음
- loopback Cloudflare HTTPS 요청은 redirect loop 없음

## 7. 열린 항목

### 7.1 과거 시험 점수 외부 원본

**상태:** 코드로 해결 불가
**필요한 것:** Google Drive/Sheet, 다른 PC, 수동 export, 별도 backup 중 하나
**다음 절차:** 원본 확보 → read-only 대조 → runtime backup → sid/test ID/round 기준 dry-run → 명시적 승인 후 patch merge

원본이 없으면 닫힌 데이터 손실로 기록하고 임의 복원하지 않는다.

### 7.2 Windows 로그온 종속 운영

감사 시점:

- Waitress 예약 작업은 `Interactive` 로그온 유형이다.
- cloudflared는 사용자 AppData config와 HKCU Run 기반 supervisor/connector다.
- 둘 다 현재는 실행 중이지만 사용자가 로그아웃하면 공개 서비스가 멈출 위험이 있다.
- 현재 프로세스 권한은 관리자 승격이 아니어서 안전하게 Windows service 설치까지 완료할 수 없었다.

**필요한 운영 조치:** 관리자 PowerShell에서 Cloudflare tunnel을 Windows service로 설치하고, config/credential을 서비스 계정이 읽는 위치로 옮긴 뒤 reboot·logout 생존 검증. Waitress도 비대화형 서비스 또는 적절한 service account 작업으로 전환한다. 이는 코드 변경이 아니라 자격 증명과 Windows 서비스 소유권 변경이라 별도 승인·승격이 필요하다.

## 8. 의도적으로 열린 것으로 보지 않는 항목

- PWA 미제공: 운영 기준에서 제거했으므로 버그가 아니다.
- `app.5a-math.com`에서 `5a-math.com`으로 이동하지 않음: 두 origin이 같은 앱을 가리키는 별칭인 현재 정책이다.
- legacy static 파일 존재: 참조가 불명확한 직접 제공 경로의 호환성 보존이다.
- demo가 live 데이터와 다름: 실서버 write를 차단하는 sandbox 설계다.
- 일부 GET의 WAL/보장 write: 현재 저장소 호환 계약이며 완전 read-only로 오해하면 안 된다.
