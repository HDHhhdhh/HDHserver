# 로컬 관리자·학생 이중 역할 사용자 테스트 튜토리얼

이 문서는 개발용 합성 학생에 연결된 **하나의 테스트 자격 증명**으로 로컬 관리자 화면과 학생 앱을 사용자 관점에서 점검하는 절차다. 비밀번호, HTTP Basic 헤더, 쿠키, CSRF 토큰, 비밀번호 해시와 Push endpoint는 문서·화면 캡처·이슈에 기록하지 않는다.

## 테스트 범위와 안전 경계

| 역할 | 접속 주소 | 기대 경계 |
|---|---|---|
| 관리자 | `http://127.0.0.1:8004/admin` | 이 PC의 loopback에서만 열리고 HTTP Basic 로그인이 필요함 |
| 학생 | `https://dev-app.5a-math.com/app` | 개발용 합성 학생 한 명의 개인 화면만 표시함 |
| 공개 관리자 차단 확인 | `https://dev-app.5a-math.com/admin` | `404` 또는 접근 불가여야 함 |

관리자 인증과 학생 세션은 서로 다른 저장소와 쿠키 경계를 사용한다. 같은 ID/비밀번호를 쓰더라도 관리자 탭을 열었다고 학생 앱에 자동 로그인되거나, 학생 로그인으로 관리자 화면이 열리면 안 된다.

## 0. 준비

1. 운영자가 별도로 전달한 테스트 ID와 비밀번호를 준비한다.
2. Chrome/Edge 계열 브라우저에서 관리자용 일반 창과 학생용 시크릿 창을 각각 연다.
3. 개발 서버가 `127.0.0.1:8004`에서 실행 중인지 확인한다.
4. 테스트 중 실제 학생 이름이나 운영 데이터를 발견하면 즉시 중단하고 화면 URL만 기록한다.

> 이 테스트 계정은 `dev-student-001` 합성 학생에만 연결되어야 한다. 실제 학생 SID를 추가하거나 운영 계정으로 재사용하지 않는다.

## 1. 관리자 모드 로그인

1. 관리자용 창에서 `http://127.0.0.1:8004/admin`을 연다.
2. 브라우저가 표시하는 “Academy Admin” 로그인 창에 전달받은 ID/비밀번호를 입력한다.
3. 관리자 화면 제목과 상단 도구가 보이는지 확인한다.
4. 주소창을 그대로 둔 채 새로고침하고 인증이 유지되는지 확인한다.
5. 별도 탭에서 `https://dev-app.5a-math.com/admin`을 열어 공개 경로가 차단되는지 확인한다.

통과 기준:

- 올바른 자격 증명으로 로컬 `/admin`이 열린다.
- 틀린 비밀번호는 `401`과 재인증 창으로 끝난다.
- 개발 공개 hostname의 `/admin`은 열리지 않는다.

브라우저가 HTTP Basic 로그인을 기억해 계정 전환이 어렵다면 모든 관리자 탭을 닫고 새 시크릿 창에서 다시 시도한다. 비밀번호를 URL(`http://id:password@...`)에 넣지 않는다.

## 2. 관리자 화면 사용자 편의성 점검

### 2-1. 주요 구역 이동

1. 상단 고정 내비게이션의 `오늘 학생`, `하원`, `캘린더`를 차례로 누른다.
2. 각 카드의 제목이 고정 내비게이션 아래에 가리지 않고 보이는지 확인한다.
3. 키보드 `Tab`과 `Enter`만으로 같은 이동이 가능한지 확인한다.
4. 화면을 직접 스크롤할 때 현재 구역 버튼의 활성 상태가 하나만 표시되는지 확인한다.

### 2-2. 기준 날짜

1. 상단 기준 날짜 입력에서 오늘이 아닌 날짜를 선택한다.
2. 오늘 학생·하원·캘린더가 같은 날짜 문맥으로 바뀌는지 확인한다.
3. `하루 전`, `오늘`, `하루 후`를 각각 한 번 사용한다.
4. 새로고침 뒤에도 같은 탭에서 선택 날짜가 유지되는지 확인한다.

### 2-3. 합성 학생 행과 작업 도달성

1. `개발용 학생` 행이 보이면 이름에 마우스를 올리고 키보드로 포커스해 요약 툴팁을 확인한다.
2. 행의 `기록`, `숙제`, `등원/결석`, `하원` 관련 버튼이 겹치지 않고 눌리는지 확인한다.
3. 하원표에서는 날짜 배지를 먼저 확인한 뒤에만 날짜별 작업을 누른다.
4. 저장을 실행했다면 토스트 메시지와 새로고침 후 결과가 일치하는지 확인한다.

개발 데이터라도 복구·삭제 성격의 버튼은 한 번에 하나씩 실행한다. 예상과 다른 학생이나 날짜가 보이면 저장하지 않는다.

### 2-4. 시험·계정·내보내기

1. 시험 관리 화면에서 카탈로그 검색과 정렬 버튼을 확인한다.
2. 학생 계정 관리에서 현재 합성 계정의 상태가 활성인지 확인하되 비밀번호 해시는 화면에 나타나지 않아야 한다.
3. 로그 내보내기 창을 열고 형식/섹션을 바꿔 본 뒤, 취소가 즉시 동작하는지 확인한다.
4. 내보낸 파일에 상담용 assistant note나 인증 정보가 포함되지 않는지 확인한다.

## 3. 학생 개인페이지 로그인

1. 학생용 시크릿 창에서 `https://dev-app.5a-math.com/app`을 연다.
2. 설치 안내가 자동으로 화면을 가리지 않는지 확인한다.
3. 관리자 로그인에 사용한 것과 같은 ID/비밀번호로 로그인한다.
4. 별도의 자격 증명 변경 화면 없이 바로 준비된 개인 홈으로 이동하는지 확인한다.
5. 표시된 학생 이름·학교·학년이 개발용 합성 정보인지 확인한다.

통과 기준:

- 로그인 후 상태가 `ready`이며 다른 학생 선택 화면이 나타나지 않는다.
- 개인 화면은 `dev-student-001` 한 명으로 제한된다.
- 로그아웃 후 뒤로 가기나 새로고침으로 보호 화면이 다시 열리지 않는다.

## 4. 학생 기능별 점검

### 홈·일정·진도

1. 홈 요약에서 다음 수업, 진도, 미완료 숙제 수를 확인한다.
2. 값이 없을 때 빈 카드가 깨지지 않고 안내 문구를 표시하는지 확인한다.
3. 화면을 아래로 당기거나 새로고침한 뒤 숫자가 중복 증가하지 않는지 확인한다.

### 숙제·시험·영상

1. `숙제`에서 제목·범위·마감일·완료 상태가 읽기 쉬운지 확인한다.
2. `시험`에서 배정된 시험과 해설 링크를 확인한다. 네트워크 정책에 따라 해설이 잠기는 것은 정상일 수 있다.
3. `영상`에서 배정 영상만 보이는지, 시청하지 않은 항목을 완료로 표시하지 않는지 확인한다.
4. 자료가 없는 화면은 오류 대신 명시적인 빈 상태를 보여야 한다.

### 공지·설치·알림

1. 공지를 열고 읽음/확인 동작이 새로고침 뒤 유지되는지 확인한다.
2. `앱 설치 안내` 버튼을 직접 눌렀을 때만 설치 안내가 열리는지 확인한다.
3. `Esc`, 닫기 버튼, 배경 클릭으로 안내가 닫히고 원래 버튼으로 포커스가 돌아오는지 확인한다.
4. Push 권한 요청은 사용자 버튼 클릭 뒤에만 나타나야 한다.

개발 Push 예약 작업은 기본적으로 비활성이다. 실제 기기 알림 수신은 별도의 VAPID·구독·1회 전송 승인 절차가 준비된 경우에만 통과 대상으로 삼는다.

## 5. 모바일·접근성 점검

1. 브라우저 너비를 약 `390px`로 줄이거나 실제 휴대전화에서 연다.
2. 가로 스크롤 없이 로그인 입력, 주요 카드, 하단 동작 버튼을 사용할 수 있는지 확인한다.
3. 텍스트가 잘리거나 버튼이 겹치지 않는지 확인한다.
4. 키보드만으로 로그인, 설치 안내 열기/닫기, 로그아웃이 가능한지 확인한다.
5. 포커스 표시가 보이고 툴팁은 `Esc` 한 번으로 닫히며 다른 전역 단축키를 계속 막지 않는지 확인한다.

## 6. 로그아웃과 역할 격리

1. 학생 앱에서 로그아웃한다.
2. `/app/home`을 직접 열어도 로그인 화면으로 돌아오는지 확인한다.
3. 관리자 탭은 학생 로그아웃과 무관하게 로컬 관리자 화면을 유지해야 한다.
4. 관리자용 새 시크릿 창에서는 다시 HTTP Basic 인증을 요구해야 한다.

## 7. 결과 기록 양식

| 항목 | 결과 | 확인한 화면/동작 | 비고 |
|---|---|---|---|
| 로컬 관리자 로그인 | PASS / FAIL | `/admin` | |
| 공개 관리자 차단 | PASS / FAIL | dev host `/admin` | |
| 관리자 주요 구역 이동 | PASS / FAIL | 오늘 학생/하원/캘린더 | |
| 기준 날짜 유지 | PASS / FAIL | 날짜 변경·새로고침 | |
| 학생 로그인·합성 신원 | PASS / FAIL | `/app` | |
| 홈·숙제·시험·영상 | PASS / FAIL | 각 학생 화면 | |
| 설치 안내·접근성 | PASS / FAIL | 버튼·Esc·포커스 | |

| 로그아웃·역할 격리 | PASS / FAIL | 세션 종료 | |

문제 보고에는 발생 시각, URL 경로, 브라우저/OS, 재현 단계, 비밀번호 입력란을 가린 화면만 포함한다. ID/비밀번호, Authorization 헤더, 쿠키, CSRF, Push endpoint와 학생 원본 데이터는 보내지 않는다.

## 운영자용 로컬 발급·검증 명령

다음 도구는 비밀번호를 명령 인자나 출력으로 받지 않고 대화형으로 두 번 입력받는다. `backup-dir`은 저장소와 runtime 밖의 접근 제한된 경로를 사용한다. 발급 전에 계정 JSON과 일관된 SQLite session backup을 만들고 Windows에서는 현재 사용자·SYSTEM·Administrators만 읽을 수 있도록 ACL을 제한한다. 같은 ID를 재발급하면 기존 학생 세션은 모두 폐기된다.

```powershell
.\venv\Scripts\python.exe -X utf8 .\scripts\provision_local_dual_role_account.py provision `
  --runtime-root <development-runtime-root> `
  --account-id <issued-id> `
  --student-sid dev-student-001 `
  --backup-dir <external-private-backup-root> `
  --confirm-local-development

.\venv\Scripts\python.exe -X utf8 .\scripts\provision_local_dual_role_account.py verify `
  --runtime-root <development-runtime-root> `
  --account-id <issued-id> `
  --student-sid dev-student-001
```

발급 파일 `instance/student-app-dev-admin-auth.json`은 Git과 일반 runtime backup에서 제외된다. 개발 Waitress에는 해당 파일 **경로만** `-AdminCredentialFileOverride`로 전달하며, production runner에는 이 옵션을 사용하지 않는다.
