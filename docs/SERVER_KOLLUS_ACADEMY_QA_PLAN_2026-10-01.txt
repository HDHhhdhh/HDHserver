현재 상태(2026-10-02): 별도 학원망 QA 실행안 준비 완료. D-18의 관리형8004 exact synthetic pair는 실제 Chrome 재생·자동watch200·90%done·수동none/reload·OFF403까지 완료했다. 별도 학원망 QA 배포·실제 외부망 차단·genuine provider callback은 미실행이며 QA 접속 대상/HTTPS 주소를 기다린다. 아래 초기 조사·관찰은 해당 시점의 이력이다.

1. 목적과 권한

기존 격리 QA의 watch 403 미검증을 해소하려면 실제 학원망 브라우저가 사용하는 별도 QA 배포와 실제 Kollus 테스트 영상이 필요하다. native 재생 → 브라우저 자동 POST → watch/progress 저장 → 관리자 및 학생 reload 상태까지 이어지는 증거와 provider가 직접 보낸 callback의 독립 증거로 합격을 판단한다.

이번 작업은 소스·문서만 읽고 이 보고서 한 파일만 작성한다. 운영 JSON/SQLite/sidecar/instance, secret, credential, 실제 영상 URL은 읽지 않는다. app import, 테스트 실행, network/browser/server 작업, source 수정, Git 변경 명령, 타 chat 메시지를 수행하지 않는다. 이 문서는 정본 규칙이나 배포 승인서가 아니다.

시작 Git 상태: staged 0개, unstaged tracked 155개, untracked 59개. 관련 watch/Kollus/controller에도 기존 변경이 있다. 아래 소스 분석은 HEAD가 아니라 현재 작업 트리 기준이다. 향후 실행 시 QA snapshot의 파일 SHA-256과 backend/frontend 동일 버전을 기록한다.

3. 현재 소스: gate와 소유권

G1 GET /api/get-url
routes/api_kollus.py:108-151, 289-321.
학원망 검사 후 public 요청이면 active SID 일치를 요구한다. MID는 [A-Za-z0-9_-] 4~128자이며 catalog에 있어야 한다. 제공한 SID는 students에 있어야 한다.
기대값: 외부망403, public SID mismatch403, 잘못된 MID400, unknown MID/SID404, 정상200.
비공개 Kollus 경로는 빈 SID도 허용한다. callback QA는 항상 명시적 QA SID를 보낸다. uservalue0 HMAC은 callback 인증용이며 DRM/license 또는 실제 재생 가능성의 증거가 아니다. 현행 URL builder의 client_ip 인자는 URL query에 들어가지 않는다.

G2 browser watch
routes/api_watch.py:38-120; core/admin_basic_auth.py:120-131.
POST /api/watch는 학원망, public active SID, 필수 date/SID/MID, 실제 달력 날짜, YouTube 제외, ghost SID를 검사한다. 비공개 POST는 admin Basic 예외지만 academy gate가 남는다. GET /api/watch는 public 요청에서404다. 현재 웹은 /api/watch를 쓰며 /api/watch-status를 새 소비자로 사용하지 않는다.
주의: 이 route 자체에는 get-url/callback의 _known_sid/_known_mid 검사나 MID 정규식 검사가 없다. public 세션 바인딩과 비공개 roster/catalog 존재 검사를 혼동하지 않는다. unknown SID/MID의 비공개 watch 거절을 이미 구현된 계약으로 주장하지 않는다. temp 특성화 후 강화가 필요하면 별도 source 변경 범위로 HUB에 반환한다.

G3 public 학생 앱
core/student_public_surface_adapter.py:130-203; core/student_app_config.py:86-99.
exact public host, HTTPS, 신뢰 proxy, 등록 path/method, 세션, active SID, 쓰기의 same-origin 및 X-CSRF-Token을 먼저 검사한다. /api/kollus/lms-callback은 public allowlist에 없다. 유효 secret도 public-host404를 통과시키지 못한다.
QA web/callback FQDN을 QA STUDENT_APP_LEGACY_HOST와 정확히 맞추고 callback을 그 host의 같은 QA instance로 보낸다. 임의 DNS alias도 자동 허용되지 않는다. legacy host의 app-only 경로 제한은 유지한다.

G4 외부 callback
routes/api_kollus.py:38-84, 154-166, 195-285, 325-390.
GET/POST 지원. KOLLUS_CALLBACK_SECRET이 비면403. browser academy gate는 적용하지 않는다.
설정 secret과 일치하는 X-Kollus-Secret 또는 query/form token, 혹은 검증된 uservalue0 signed token 중 하나가 필요하다. JSON body의 단순 token이나 callbackTokenValid=true는 인증 근거가 아니다.
v1: SID/MID/issued_at에 HMAC-SHA256. v2: cycle token도 포함. 발행 후24시간, 미래 skew5분 허용.
정적 secret과 signed token은 OR 관계다. 변조/만료 negative에는 유효 정적 secret을 같이 보내지 않는다.
인증 후 missing SID/MID400, bad MID400, unknown SID/MID404, YouTube400. 진도 필드가 전부0이면200 ignored:true/무쓰기.
callback 날짜는 start_at epoch seconds의 KST 날짜다. 잘못되거나 없는 값은 현재 KST 날짜로 fallback하므로 실제 시험은 seconds와 날짜 일치를 확인한다.
done은 pct>=90 또는 last/dur>=0.9다. dur>0일 때 interrupted는 pct>=5를 사용한다. last/dur만5%이고 pct가 없으면 현재 route는 interrupted를 만들지 않는다. canonical §10의 일반5% 설명과 실제 provider payload를 대조해야 한다. 실제 pct 누락은 계약 차이로 반환하며 값을 주입해 통과시키지 않는다.

O1 native iframe → browser watch
static/js/student/playback.js:76-172, 175-198, 200-247.
VgControllerClient가 iframe contentWindow에 붙고 ready/progress/play/pause/done 및3초 poll을 부모 window의 자체 message로 전달한다. handler는 event.source === 현재 window, active MID 일치를 요구한다. iframe의 직접 message를 그대로 저장하는 구조가 아니다.
attach는100ms 간격 최대200회. timeout 경고는 native/bridge 미성공 증거다. 90% 또는 ended로 completed를 만든다. MID 전환은 이전 flush 후 새 generation을 연다. 오래된 poll/get-url 응답이 새 MID를 덮으면 실패다.
static/js/student/watchState.js:183-245; student.js:930-1027.
watchState: SID별 local resume/watch, monotonic merge,1500ms debounce, 실패 후 재시도 가능한 snapshot, duplicate-send 억제, ms updatedAt, /api/watch transport.
student.js: DOM badge, active SID, local date, academy access, pagehide/visibilitychange/beforeunload keepalive flush 주입.
get-url200만으로 automatic watch 성공을 선언하지 않는다. browser local date와 KST를 맞춘다.

O2 서버 저장
core/watch_progress_writer.py:40-84, 100-195; core/progress_rules.py:13-32, 310-374.
browser/callback은 같은 path-injected writer를 쓴다. last/dur/updatedAt은 큰 값, completed는 OR이며 unknown MID metadata를 보존한다. seconds/32비트 timestamp는 현재 server ms로 교정하고 유효 ms는 보존한다.
__manualProgressMids와 수동 none/skip/interrupted가 자동 진도보다 우선한다. 자동 interrupted는 done으로 승격한다.
UI assigned는 updates membership의 초록이다. 정상 영상 progress 값 목록에는 assigned가 없다. literal progress에 assigned를 넣어 fixture를 만들지 않는다.
watch와 progress는 별도 저장 경계다. stale cycle browser 요청은 raw watch 이력을 저장한 뒤 progress를 보존하며409 watch_cycle_changed를 반환할 수 있다. 오래된/세대 없는 callback은 과거 watch를 보존하지만 새 cycle을 완료시키지 않는다. 전체 저장의 동시 원자성을 이미 구현된 것으로 주장하지 않는다.
유효 callback 재전송은 updatedAt이 증가할 수 있다. 멱등성은 상태·배정이 반복 완료/재배정되지 않는 의미이며 모든 성공 뒤 파일 mtime/hash 불변을 뜻하지 않는다.

7. 승인 후 실제 실행 순서

P0. manifest와 source baseline
승인된 머신/경로/host/network/provider 범위와 QA-only credential 참조를 대조하고 S 케이스를 임시 경로에서 검증한다. 필요한 fixture/harness 작성은 이번 report 권한 밖이며 후속 QA edit scope에서만 수행한다. 생산 환경변수를 상속한 app/test import를 하지 않는다.

P1. 별도 QA 배포와 synthetic 등록
승인된 runner/ingress로 QA만 배포한다. startup recovery/default 생성도 QA 경계인지 paths를 먼저 확인한다.
synthetic 학생/과정/영상 역할을 정상 QA 절차로 등록한다. A는 현재 KST 수업 대상/auto count3, B는 callback-only 학생이다.
A의 오늘 snapshot을 한 번 생성하고 세 MID 순서/source:auto를 확인한다. baseline 뒤 count/과정/일정/결석을 변경하지 않는다. 다음 후보 spare를 catalog에 남긴다. 관찰용 updates 요청은 ?readOnly=1이다. 자정 경계를 피하고 browser local date를 KST와 맞춘다.
QA listener/HTTP/ingress, JSON/DB/sidecar 경계와 생산 ping/public app 가용성을 별도로 기록한다.

P2. 실제 네트워크 gate
실제 학원 Wi-Fi/LAN의 정상 요청으로 get-url200과 academy 분류를 확인한다. 실제 외부망에서 get-url/watch403과 제한 DOM을 확인한다. header spoof/route interception으로 academy=true를 만들지 않는다.
public 실표면 범위이면 실제 QA 학생 session/CSRF로 자기 SID 성공, 다른 SID403, session 없음401, CSRF 없음403과 실패 store 불변을 확인한다. 관리자 Basic은 유지하고 Chrome 정상 로그인으로 검증한다.

P3. browser-only native 자동 watch
provider QA callback delivery를 아직 등록하지 않은 단계에서 QA secret은 설정해 둔다. browser와 callback의 진도 원인을 섞지 않는다. 단계별 provider 설정은 QA channel/video 범위에만 승인된 소유자가 수행한다.
Chrome 학생 페이지를 reload하고 actual script 순서와 #player 하나를 확인한다. 첫 영상의 iframe/native 준비, 시간의 실제 증가, duration, bridge ready/event/poll을 관찰한다. manual postMessage/completed:true fetch/90% seek로 실제 시청을 대체하지 않는다.
5% 뒤 debounce 자동 POST /api/watch200, stored interrupted/auto metadata, 관리자 주황/학생 badge를 확인한다. 90%와 끝까지 실제 시청한 뒤 completed:true/progress done, 관리자 파랑/reload 유지, today auto 완료행 유지, snapshot 불변/spare 미보충을 확인한다.
MID 전환 flush와 active MID 한정 반영, pause/숨김/pagehide/재접속 POST/resume도 관찰한다. 실패 재시도는 허용된 QA watch 요청만 대상으로 하며 전역 network/운영 연결을 변경하지 않는다.

P4. browser-only 실제 manual white 보존
white 영상을 5~10% 실제 재생하여 새 observation을 만든다. Chrome 관리자 log/unified popup의 exact SID/date 진도 셀을 흰색으로 저장한다. 응답과 GET /api/progress에서 none과 __manualProgressMids[mid]=true를 확인한다. assignment 삭제를 manual none 대신 사용하지 않는다.
계속 재생하여 last/completed가 달라진 자동 POST200을 발생시킨다. 90%/done 뒤에도 none/manual marker/관리자 흰색이 유지돼야 한다. 관리자 reload/open, 학생 reload, automatic watch refresh 뒤에도 확인한다. 수동 action 직후 baseline으로 intentional admin write와 후속 automatic write를 구분한다.
QA에서 /api/logs 및 /api/logs/entry, Korean notes/unknown fields/다른 SID·date/frozen date를 확인한다. 다른 SID/date popup을 연 뒤 늦은 이전 watch가 새 셀을 바꾸지 않는 회귀 gate도 유지한다.

P5. genuine provider callback-only
승인된 소유자가 QA video/channel에만 exact legacy callback URL을 설정한다.
B의 get-url로 발행한 uservalue0를 쓴 QA provider 재생을 Chrome 별도 provider 탭에서 실행한다. 그 탭에 student.js/watchState가 없고 B의 browser /api/watch가 0건인지 관찰한다.
provider genuine delivery ID/시각 + ingress path/peer + callback200 + B의 저장 변화를 연결한다. 운영자의 synthetic POST를 외부 provider 성공으로 세지 않는다.
실제 5%/90%/done payload의 pct/last/dur/start_at/uservalue0 echo를 redaction 후 검증한다. B의 interrupted→done, ms, snapshot 불변을 확인한다. 별도 역할 영상에서 B의 manual none/skip/interrupted 뒤 genuine callback에도 수동 상태가 유지되는지 확인한다.
재전송/늦은 callback은 실제 delivery와 monotonic으로 평가한다. 변조/만료/MID mismatch는 별도 synthetic/temp이며 genuine provider로 표시하지 않는다.

P6. 두 경로 결합과 새 watch cycle
fresh synthetic SID/role baseline에서 browser watch와 provider callback을 함께 켠다. 양 route의 순서/중복 뒤 상태 후퇴 없음과 배정 미보충을 확인한다.
관리자의 explicit assigned 재배정으로 fresh cycle을 만든다. get-url v2/X-Video-Watch-State/latest resume0/browser cycleToken을 확인한다. 과거 완료 raw watch가 새 세대에 합쳐지면 실패다. 실제 새 재생의 5%/90%와 current v2 callback만 승격해야 한다.
old session/stale 요청의 synthetic 증거와 실제 delayed delivery 증거는 구분한다.

P7. 브라우저 결과와 QA 종료
Chrome의 실제 native 성공은 필수다. 학생 DOM/한글/제한/playlist/manual 상태는 Chrome/IAB 각각 남긴다. IAB native 실패는 미검증/실패로 기록하며 Chrome 성공을 복사하지 않는다. 기존 manager8004의 두 브라우저 회귀 gate도 유지한다.
console errors, API 실패, player/bridge timeout, native 상태를 분리한다. provider 오류를 숨기지 않는다. 지원 native 브라우저 범위 축소는 HUB의 별도 결정이며 D-10을 자동 재사용하지 않는다.
QA callback 등록/ingress/secret 폐기는 승인된 소유자가 허용된 한도 안에서 수행한다. QA data의 생산 승격은 없다. 공유8004는 소유권/사용 확인 없이 Stop하지 않는다. production restart는 이 QA의 완료 단계가 아니다.
