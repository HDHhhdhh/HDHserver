범위

이 숫자는 실제 브라우저에서 모든 분기를 새로 통과한 횟수가 아니다.

합성 서버 데이터만 사용했다. 운영 JSON·SQLite를 QA seed로 복사하지 않았다.

구현
1. 테스트 저장 버튼은 첫 요청 전에 저장 중 표시와 편집 잠금을 적용한다.
   같은 세션의 중복 저장을 공유하고, 새 세션의 표시를 이전 응답으로 복원하지 않는다.
   진도 및 후속 로그 성공 뒤 완료 표시, 부분 실패 안내와 재시도 초안은 유지한다.
2. 로그 JSON 저장은 LogRepository에서만 compact 형식을 사용한다.
   SQLite·JSON 이중 저장, 잠금, 원자 교체, 동기 미러, 미지 필드 보존은 유지한다.
   복구용 좁은 snapshot은 원래 canonical JSON 형식도 기록한다.
   pretty/compact 복구와 기존 형식 정보가 없는 저널을 구분한다.
3. 통합 저장은 앞선 기록의 SQLite·JSON 성공을 정확한 true로 확인한다.
   최신 로그의 이월 필드가 전부 같을 때만 중복 POST 1개를 생략한다.
   영상→기록→이월→시험 마지막 순서, 최신 GET, 부분 실패 복구 쓰기는 유지한다.
4. 보강 명단의 선택 Set, 첫 일치 SID Map, 타임 라벨을 렌더 안에서 재사용한다.
   결석·보강의 새 빈 검색 행에는 같은 표시 상태를 다시 쓰지 않는다.
   닫거나 다시 연 뒤 이전 예약 포커스를 실행하지 않는다.
5. 테스트 드래그의 최근 보기 저장은 범위 변경마다 1회 수행한다.
   상태·변경 순서·범위 되돌리기·기존 마지막 유효 행의 값은 보존한다.
6. CSV 저장 완료는 필수 카탈로그 저장·revision 재조회·표시를 기다린다.
   통계 조회는 별도로 진행하고 최신 세대만 화면에 적용한다.
7. 숙제 미흡 알림은 첫 조회 중 등록한 새 항목을 늦은 조회/조회 실패에도 보존한다.
   같은 ID 중복을 제거하고 학생 과목 lookup은 렌더마다 한 Map을 사용한다.
8. 파일 이동은 저장 실패와 저장 성공 후 목록 조회 실패를 구분해 안내한다.
   최신 파일 트리 조회와 기존 배정 쓰기 안전 경계는 유지한다.
