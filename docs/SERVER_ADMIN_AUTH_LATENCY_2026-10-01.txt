제안 동작
- 환경-backed username/hash를 모든 요청에서 새로 읽는다.
- 원래 _configured_value와 _basic_credentials를 수정하지 않았다.
- username 비교식과 check_password_hash 호출/기존 TypeError·ValueError 실패 처리는 그대로다.
- 완료한 성공만 5초의 고정 TTL로 재사용한다. hit는 TTL을 연장하지 않는다.
- 성공은 최대 64개, 진행 중 record는 최대 8개. 저장하는 자격증명 키와 설정 식별자는
  process-local 256-bit 난수 secret의 HMAC-SHA256 digest이다.
- 캐시에 평문 비밀번호, 원래 Authorization, username 문자열, password hash 원문을 보관하지 않는다.
  성공 map은 digest→expiry, 진행 map은 digest→Event, 설정은 digest만 보관한다.
- 같은 성공의 cold concurrent 요청은 KDF 한 번을 공유한다.
- 실패는 캐시하지 않는다. 대기 뒤 성공 cache가 없으면 각 요청은 자기 KDF를 병렬 실행한다.
  진행 중 검사 대기는 성공 TTL과 독립적이다. 소유 검사의 finally 또는 설정 무효화가
  대기자를 깨우며, 포화 시에는 자기 전체 KDF 검사를 실행한다.
- username/hash가 바뀌거나 누락되면 기존 성공과 진행 record를 무효화하고 대기자를 깨운다.
- KDF 또는 hit 전후에 환경-backed 설정을 재관찰한다. 진행 중 설정이 바뀐 결과도 거부한다.
- 설정의 unpaired surrogate는 fingerprint/HMAC와 username 비교에서 안전하게 False로 처리하며
  기존 성공을 무효화한다. 새로운 인증 허용 범위를 추가하지 않는다.
- 실패·최초 요청·TTL 만료·설정 변경은 전체 KDF를 유지한다. hash method/params는 바꾸지 않았다.
- 보호 경로, 네트워크 해석, API exemptions, challenge/no-store headers, 계정 비밀번호는 변경하지 않는다.
- cache는 process-local이고 디스크 저장은 없다. 프로세스 재시작/다른 프로세스에는 성공이 공유되지 않는다.
  TTL 만료 항목의 정리는 다음 조회에서 수행되며, 만료된 항목은 인증을 허용하지 않는다.
