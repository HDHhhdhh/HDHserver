provider 단독 영상 재생과 테스트 학생의 자동 저장은 별개의 결과로 관리한다.

실행·검증 범위
1. 조건을 하나씩 누락한 요청과 다른 학생·영상은 기존처럼 거부되고 저장되지 않는지 확인한다.
2. 실제 iframe 재생 → 자동 POST200 → QA watch/progress 저장 → 재조회·reload를 확인한다.
3. 밀리초 시각, 수동 none 보존, 배정 snapshot 불변을 확인한다.
4. 시험·자료·인증 제한과 기존 관련 회귀, 전체 non-smoke suite를 확인한다.
5. QA 예외를 끄고 두 서버의 가용성을 확인한다. QA 데이터는 운영에 병합하지 않는다.

대안: 실제 학원망에 별도 격리 QA 배포 연결
새 host·runner·배포 범위가 필요하다. 현재 8004를 외부에 노출하는 것으로 대체하지 않는다.

사용자가 ‘8004 영상 전용 QA 예외 승인’이라고 명시 승인했다. D-18과 core/isolated_kollus_qa.py에 경계를 기록하고 manager -KollusVideoQa로 검증 중에만 활성화했다. 합성 학생은 격리 저장소의 기존 저장 함수를 사용해 추가했고 운영 add-student의 ID 생성 규칙은 변경하지 않았다. 영상·배정·초기 progress는 QA의 정상 API로 설정했다.

실기동에서 발견·수정한 저장 문제
공식 legacy SDK 2.0.2에는 getPosition/getDuration/seek가 없다. 실제 prototype과 공식 문서에 맞춰 get_progress()/set_current_time()을 사용하고 VM fixture도 해당 계약으로 정렬했다.
실제 1초 progress 이벤트가 1500ms debounce를 계속 미뤄 재생 중 저장되지 않고 reload/pagehide 때만 저장됐다. 기존 trailing debounce와 함께 MID별 고정 10초 저장 시도를 추가했다. flush/reset/cycle 변경 시 두 timer를 취소하며 실패 재시도·중복 제거·접근 제한은 유지한다.
실제 연속 재생에서 약 10초 간격의 자동 POST200을 확인했다. 340초/2143초 저장과 interrupted·epoch-ms·배정 marker 보존, 새로고침의 16%/이어보기 복원도 확인했다. Chrome와 IAB의 학생 표시·재조회는 확인했으며 native 재생은 Chrome의 증거다. 완료·수동 none 검증은 아래 최종 결과에 기록한다.
최종 소스의 non-smoke 전체105그룹, board/notifications22assertions, focused SDK/watch/timestamp/rearm 및 QA103assertions/실제 entrypoint 검증이 통과했다.
