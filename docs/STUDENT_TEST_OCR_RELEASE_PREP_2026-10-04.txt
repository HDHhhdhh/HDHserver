운영 적용 순서 (계획만이며 이번에 실행하지 않음)
  독립 품질·실제 전체 속도 확인 → 검토된 모델/증거/적용·복구 계획
  → 명시적 유지보수 승인 → 정지 상태의 검증된 백업 → 검토된 migration/모델 경로 적용
  → 승인된 재시작·점검 → 명시적 기능/유지보수 활성화 → 운영 관측

1. 새로운 자연 필체 학생 holdout을 승인된 용도로 수집한다. 이전 학습·튜닝 작성자와 종이·변형을 제외한다.
   별도 실제 전사 검토와 평가 전 고정, 작성자 군집·운영 분포 검토를 기록한다.
2. 같은 후보/모델 설정/코드/정책으로 세 경로와 실제 20문항 흐름을 검증한다.
   실제 첫 촬영·전체 재촬영·객관식 보완·수식 최대2회 재촬영·보류·당일 확정·최초/최종 채점 trace를 확보한다.
   실제 정답을 오답으로 확정한 오류는 OCR 전사 오류와 별도로 검토한다.
3. 대상 서버에서 cold/warm·대기열·crop·추론·채점 저장 범위를 구분해 측정한다.
   실제 카메라 안내틀 변환과 렌더링을 검증된 frontend 바이트에 묶는다. source fixture는 이 검증을 대신하지 않는다.
4. 반환 모델의 실제 checkpoint/공통 architecture/tokenizer SHA와 원래 receipt를 검증한다.
   3단계의 미수신 parts와 후보 검증은 계속 남아 있다. receipt 경로를 현재 서버 경로로 추정하지 않는다.
5. 품질/속도 gate와 검토 증거를 통과한 뒤 적용·중지/재시작 횟수·복구 계획을 별도로 승인받는다.
   8004는 관리자로 운영하는 loopback 격리 서버만 사용하며 운영 데이터를 테스트 seed로 복사하지 않는다.
6. 승인된 정지 유지보수 창에서 python scripts/backup_runtime_data.py로 백업을 만들고 검증한다.
   현재 SQL은 scripts/migrations/20260828_create_student_test_ocr.sql이다. 존재 확인은 적용 승인이나
   현재 schema와의 호환 확인을 뜻하지 않는다. 검토한 일방향 migration을 적용하고 별도로 검증한다.
7. 모델은 검증된 새 경로로 배치하고 기존 모델/자료는 보존한다. 새 경로·정책·코드의 실제 증거를 확인한다.
   승인된 횟수만 운영 서버를 재시작하고 서버/학생 공개 페이지/새 기능을 확인한다.
8. 기능과 별도 보관 scheduler 활성화는 승인된 적용 단계에서만 한다. 실패 시 승인된 복구 계획을 사용한다.
   student crop 7일 삭제·당일 보류 처리를 실제 운영에서 확인한다. 학습 corpus를 삭제 대상으로 혼동하지 않는다.
