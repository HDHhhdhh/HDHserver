# SCRIPTS KNOWLEDGE BASE

## Overview
Scripts cover verification, runtime backups, generated test catalog files, answer-link maps, and import utilities.
Business meaning is owned by [the Server Rules Index](../docs/SERVER_RULES_INDEX.md);
this file owns operational-script and verification safety.

## Conventions
- Treat scripts that write root JSON, SQLite, `tests-config.json`, or generated maps as operational changes.
- Every route-test persistence path must point to an OS temporary directory even when its writer is mocked. When a route gains a new writer, update both the mock and the path guard before running the test; a stale mock must never fall through to a live store.
- Before bulk repair or migration, create a backup with `python scripts/backup_runtime_data.py`.
- Person identity live migration is exceptional: only `migrate_person_identity.py --apply` may initialize a missing `persons.json`, and only after its reviewed-plan, matching-backup, explicit-confirmation, and stopped-listener checks pass. Ordinary verification, imports, and routes must never auto-create a missing identity directory or repair configured partial state by falling back to roster-only writes.
- The root `today_order.json` is retired. Do not add it back to fingerprints or deployment lists; canonical today order is `data/today_order.json`.
- Main verification commands:
  ```bash
  python -m compileall -q app.py routes core scripts
  python scripts/verify_refactor_safety.py
  python scripts/verify_refactor_safety.py --smoke
  ```
- Keep generated CSV/debug/image outputs under `generated/`.
- Compile/default verification can create `__pycache__` and root `tmp/` artifacts. `--smoke` imports the live app, performs selected GETs, and permits WAL/SHM changes.
- Full-app standalone verifiers are runtime-sensitive even when their assertions are read-only; fingerprint all relevant stores before using them.
- Concurrency verifiers must observe locks/queues from outside the implementation. Do not import a production revision helper to calculate the expected revision, inspect a queue's private state as proof of serialization, or substitute source markers for actual route/file behavior.
- For test catalog updates, keep student answer links in sync:
  - `REVIEW` and `SCHOOL_PAST`: preserve/update `sourceFiles.solutionFileId` or equivalent metadata.
  - `UNIT`: regenerate/update `static/js/test_answer_link_map.json` from Drive explanation files.
- Exercise catalog writers with temporary `--config`, `--csv`, `--output`, and `--issues` paths where supported. REVIEW/SCHOOL_PAST imports and the answer-map builder enforce `--backup-confirmed` for live outputs.
- UNIT replacement import and `seed_tests_config.js` now require explicit backup confirmation and reject implicit ID removals; `--allow-unit-removal` is required for an intentional shrink. Append/sort remain live mutators, so back up first and do not assume every script accepts temp-path or confirmation flags.
- The tracked canonical answer map is `static/js/test_answer_link_map.json` with `sourceId -> round -> entry`. The retired `static/js/test_answer_link_map.js` wrapper and `/js/test_answer_link_map.js` URL must stay absent and must not be ignored or regenerated.
- SQL files in `migrations/` are manual artifacts, not an executable chain. The current assistant-note create/add-column files conflict if applied sequentially; reconcile them before any live migration.
- Student OCR verification must use temporary SQLite/assets and injected services. The migration and feature flag stay separate, and official solution-crop checks use temporary PDFs or the ignored local cache without writing the live catalog.
- Browser evidence under `.omo/evidence/` is ignored local QA output and is validated only through the explicit `--only-frontend-evidence-inventory` selector; the default safety suite must remain reproducible without it.
- `tests-config.json` is ignored runtime data. The default safety suite uses a synthetic UNIT answer-material contract; validate the current local catalog separately with `--only-unit-test-answer-material-readiness`. Retired student submission checks must assert route/UI absence while preserving admin assignment coverage.
- Video verification layers are complementary: the default Python suite covers pure/server assignment, bootstrap, self-study, and watch rules; `verify_student_bootstrap_state.mjs` covers browser load/projection ownership; the watch verifiers execute local state/sync literals; `verify_student_playback.mjs` independently executes resume, URL, iframe bridge, progress message, and failure behavior; `verify_student_review_playlist.mjs` executes local key/prune/order/idempotence/isolation with input hash invariance; `verify_student_previous_video_review.js` covers the pre-existing student DOM; `verify_student_material_access_scope.js` covers academy restriction; `verify_video_manage_ids.mjs` covers catalog row IDs plus the normal/correction-mode browser source contract. Do not treat one as a substitute for the others.
- Announcement verification layers are complementary: `verify_student_announcement_state.mjs` is a DOM/transport-free literal state oracle, student-mobile `board`/`notifications` executes the pre-existing entrypoint, deep-link, and shell contracts, `verify_announcement_image_access.py` covers server membership/access, and two-browser isolated QA covers the real student surface. Do not replace these with source-string checks alone.
- Student-test presentation verification layers are complementary: `verify_student_test_presentation.mjs` is the literal/hash oracle, `verify_student_answer_mobile.js` preserves navigation/source seams, `verify_student_material_access_scope.js` executes the pre-existing restricted card and click in the real entrypoint VM, retired-submission checks keep writes absent, and two-browser isolated QA covers the rendered card. Do not treat the new oracle as its own ground truth.
- Test-catalog verification layers are complementary: the three `verify_test_catalog_*_state.mjs` oracles use literal expectations and input hashes against the pure catalog/editor/statistics modules; `verify_tests_stylesheet_extraction.mjs` binds the external stylesheet to the normalized pre-extraction CSS hash, cascade order, and approved current shell-body hash; `verify_test_catalog_search_and_sort.mjs` executes the actual entrypoint's reorder/search/409/rollback behavior; mobile-touch and the two admin record-detail UI VMs read the real extracted stylesheet; the Python detail contract independently covers payload safety; `verify_test_answer_modes.py` preserves core/network/migration evidence; `verify_tests_config_write_safety.py` exercises the temp Flask revision/delete boundary; and two-browser isolated QA covers rendered and computed styles. Do not replace the existing entrypoint/backend/browser layers with a new oracle.
- Admin CSS inventory verification is not rendered proof: keep its pre-split hash and literal consumer scan, the existing feature verifier, and the later two-browser computed-style comparison complementary. The ownership and decision queue live only in `docs/ADMIN_CSS_INVENTORY.md`.
- Keep `verify_student_bootstrap_routes.py` independent of production expectation builders: expected payloads are literals, route ownership is inspected through Flask, auto initialization is observed only through the injected callback, and every temp store is checked by bytes plus SHA-256.
- Automatic video verification must prove non-today loads and future schedule events are storage-only, future progress/watch does not affect today's candidates, future named `source:auto` PATCH writes fail without changing bytes/hash even when the incoming fragment omits `source`, explicit future-auto removal/reclassification succeeds, non-boolean `remove` values cannot delete, real-today initialization removes only future-auto residue, values above 6 affect a newly created snapshot as 6 without rewriting the roster, existing dated snapshots remain byte/hash-identical after completion, count setting changes do not touch assignments, and only the real current KST date can receive a new `source:auto` snapshot. Keep the new-absence removal exception in the independent absence transaction suite. Fault-inject post-commit initialization for extra, weekend, and student schedule/curriculum writers; the identical request must replay the hook from persisted source state without changing successful response contracts.
- Makeup sheet sync must use `routes.absence_assignment_cleanup.absence_write_scope` plus `commit_new_absences_locked` with canonical paths. Keep network reads before live locks and dry-run mutation-free. Live writes must preserve updates → progress → logs → absence → carryover semantics while every synchronous failure rolls all stores back and an unfinished crash journal is recoverable.
- Keep every review fixture `done`-only. An `interrupted` fixture is intentionally excluded by `student.js` and cannot be used to assert that a restricted review row renders.
- Normal-mode video catalog tests must not exercise live files. Keep `verify_video_mid_change_guard.py` temp-only and reject any reintroduction of `_migrate_video_mid_references()` or a normal `/api/videos` guard bypass.
- Correction drafts and runtime backup archives are sensitive local artifacts and must not be committed. Live MID correction is permitted only through the PowerShell wrapper with both `-Apply` and `-ConfirmApply`; do not invoke the Python `--apply` path against the live root by hand.
- Keep `verify_student_watch_timestamp.mjs` and `verify_watch_timestamp_guard.py` green; they reject 32-bit/10-digit `updatedAt` values and prove browser-to-server millisecond preservation/repair.

- JSON transport/owner/mirror 변경은 `verify_json_store_transport.py`, `verify_json_store_owners.py`, `verify_async_mirror.py`를 기본 suite에서 함께 실행한다. 실제 module·OS-temp·native lease·독립 literal/hash·오류 무쓰기와 whole auth blueprint를 유지한다. 비동기 worker 검증은 event/drain을 쓰며 temp cleanup 전에 worker/child를 종료한다. 기존 즉시 fingerprint fixture는 `DATA_MIRROR_SYNC=1`을 사용하되 async verifier의 별도 비동기 모드를 유지한다.

## Anti-Patterns
- Never launch another `app:app`/Flask server directly from the live root while production is running. Use `manage_isolated_design_server.ps1` when port 8004 is required; it is the only supported concurrent-server path.
- Do not commit runtime backup archives, generated CSVs, debug screenshots, or local Drive downloads unless explicitly requested.
- Do not run import/seed scripts casually; they can change `tests-config.json` and visible student behavior.
- Do not make smoke checks that mutate runtime data without fingerprinting and reporting it.
- Do not treat generator exit code `0` uniformly as issue-free; some builders still emit warning/issue artifacts.
