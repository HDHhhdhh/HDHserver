# FRONTEND JS KNOWLEDGE BASE

## Overview
Browser behavior is split between admin modules, all-page modules, shared helpers, and large standalone student/test scripts.
Business meaning is owned by [the Server Rules Index](../../docs/SERVER_RULES_INDEX.md);
this file owns browser edit and verification constraints.

## Conventions
- When adding or touching JSON request wrappers, prefer `shared/api.js` or page-specific wrappers over fresh ad hoc fetch helpers.
- Preserve endpoint URLs, payload keys, credentials/cache options, and existing response shapes.
- `todayLocalKey()` means real local date. Admin selected-date behavior belongs in `static/js/admin/core/adminDate.js`.
- Student bootstrap `assignedTests` stays a top-level array and its server-projected `answerUrl`/`answerRestricted` fields are authoritative. `student/testPresentation.js` owns read-only normalization, labels, answer-access/card projection, pending count, and same-tab rules without DOM/fetch/storage; `student.js` owns card elements and click feedback. The distinct `student-test-ocr-launcher.js` may add a default-off camera action only after capabilities and server eligibility succeed. Never add client-side grading, answer keys, or answer-map fallback hooks.
- Student OCR uses live `getUserMedia` only, preserves the one-time launch token in sessionStorage, and follows server actions: 1~3 uncertain questions get choice/crop correction, 4+ require a full retake, and a second failed subjective recapture becomes teacher-pending. Administrator review may expose official crops only through Basic-auth no-store endpoints.
- Student bootstrap is also the sole authority for `reviewVideos` membership. Normalize only deduplicated `reviewStatus: "done"` rows, preserve chapter order, and never infer candidates from `/api/videos`, progress/watch, or localStorage. If bootstrap fails, surface the load error and stop instead of reconstructing partial state from legacy endpoints.
- `student/bootstrapState.js` owns the non-public concurrent `/api/watch/latest` + `/api/student/bootstrap` load, the injected public-session load, and the existing nine-slot initial-state projection. It must remain DOM/storage-free, and `student.js` must only update the active public SID before consuming the projected state.
- `student/watchState.js` owns SID-scoped resume/watch keys, monotonic local/server merge, full epoch-millisecond timestamps, duplicate-send suppression, 1500 ms debounce, retryable failed saves, and injected `/api/watch` transport. Keep it DOM-free and ambient-storage-free; `student.js` injects current SID/date/access/player state and owns lifecycle listeners plus badge rendering.
- `student/playback.js` owns the active MID, resume query projection, `/api/get-url`, HTTP→HTTPS upgrade, iframe Kollus attachment/polling, same-window active-MID message gate, and 90%/ended browser completion event. Keep DOM lookup, SID, access, watch state, timers, URL/request, notices, and logging injected; `student.js` owns playlist selection, player ready/empty presentation, and board-scroll orchestration.
- `student/reviewPlaylist.js` owns the injected `student:review-playlist:<sid>:<date>` key, stored-MID normalization, fresh-authority prune, insertion-ordered pending selection, registration, and cancellation. Keep it DOM-, fetch-, and ambient-storage-free; `student.js` injects SID/date/storage and retains authoritative `reviewVideos` normalization, access/blocking decisions, rendering, and playback composition.
- `student/announcementState.js` owns strict announcement/board normalization, pending/completion semantics, acknowledgement/survey/reply transitions, the three-reply limit, board filtering, and deduplicated pagination. Keep it DOM-, fetch-, and ambient-storage-free; `student.js` owns endpoint calls, modal/carousel/form DOM, accessibility, scroll/focus, and user-visible success/error feedback.
- `student/testPresentation.js` preserves unknown fields while deduplicating assigned tests, keeps the existing status/difficulty labels and answer URL aliases, treats academy access as the link-opening gate, and projects card metadata plus mobile/tablet same-tab behavior. Keep it DOM-, fetch-, and ambient-storage-free; `student.js` owns `<a>`/`<button>` creation, target/rel, disabled state, and academy-only notices.
- The “영상 등록” button only appends checked authorized MIDs to the visible playlist and local review controller. It performs no fetch. Checkbox/title clicks select only; playback starts from the main playlist row.
- Assigned and registered-review rows share the one injected playback controller, `/api/get-url`, Kollus bridge, local resume state, and `/api/watch`. Outside the academy, keep review rows title-only and non-actionable; do not issue get-url or watch requests.
- The current web student uses `/api/watch`. Do not introduce `/api/watch-status` calls here; that older endpoint remains temporarily only for the separately developed student app until its migration and merge.
- A server-authoritative bootstrap may intentionally reintroduce a manually reopened assigned video. Clear only that visible assigned MID's stale local completed cache; never apply this repair to unrelated review/history rows.
- Watch `updatedAt` is epoch milliseconds. Never apply bitwise integer coercion such as `| 0` to timestamps; keep `verify_student_watch_timestamp.mjs` and the literal watch-controller oracle green whenever snapshot serialization changes.
- File-manager assignment changes must fetch `X-Material-State-Revision` immediately before editing and POST the whole map with `If-Match`; show a reload/retry message on 409 and a read-only recovery message on 503. Keep the temporary no-header compatibility path until the already-running old backend is normally restarted.
- The retired `ensureTodayAssignmentIfMissing()`/last-assignment writer must not be restored in `student.js`; server snapshots and bootstrap own automatic assignment.
- Answer precedence is assignment/config direct URL, `sourceFiles.solutionFileId`, then canonical JSON map. Academy-network gating strips/blocks every layer.
- `video-manage.js` may add rows and edit metadata or a signed URL that resolves to the same MID. If an existing ID is removed or its MID changes in normal mode, restore the last saved catalog and show the persistent protection warning; the server 409 remains authoritative.
- Correction mode starts from a clone of the last saved catalog, disables normal save, suppresses auto-save POSTs, and may only download the versioned draft. Cancel restores the saved clone. Never add a browser apply endpoint or persist the draft in localStorage.
- [`RULE-TEST-001`](../../docs/SERVER_RULES_INDEX.md#rule-test-001) splits `tests.js` writes: individual test definitions use revisioned `PATCH /api/tests-config/test` with explicit `clearFields`; global rules, bulk changes, and deletion use revisioned `POST /api/tests-config`. On 409/428, restore or reload the authoritative snapshot before another edit. Never save a network-stripped GET representation or drop source metadata, unknown fields, answer rounds, or untouched tests.
- `tests/catalogState.js` owns config/test normalization, catalog search/sort/grouping, reorder blocking, revisioned POST/PATCH request projection, and deep rollback snapshots. Keep it free of DOM, fetch, storage, and API endpoint strings; `tests.js` remains the owner of endpoint calls, mutation timing/locks, rendered rollback, CSV/editor DOM, and feedback.
- `tests/catalogEditorState.js` owns answer parsing, answer-mode normalization/validation/summary, round-preserving answer merge projection, CSV template/cell/parser/header aliases, and per-row answer/mode projection. Keep it free of DOM, fetch, file/blob APIs, storage, and endpoint strings; `tests.js` owns file reads/download clicks, editor elements, catalog mutation/save, and feedback. Preserve the approved compact-answer contract (`1342` is one token plus padding), and keep the rendered help limited to delimiter-separated multi-answer examples.
- `tests/catalogStatisticsState.js` owns statistics labels, id/signature/name lookup precedence, summary/table/search/sort projection, metrics, API-detail-only answer links, record rows, and wrong-answer comparison projection. Keep it free of DOM, fetch, storage, and endpoint strings; `tests.js` owns `/api/tests-stats` and `/api/tests-records` timing, escaped table/modal HTML, click/close events, and feedback.
- [`RULE-CALENDAR-001`](../../docs/SERVER_RULES_INDEX.md#rule-calendar-001) requires `school-cal.js` to delegate pure document/row projection to `school-calendar/state.js`, and its no-store GET plus all auto/switch/flush/metadata writes to `school-calendar/persistence.js`, which composes the single `shared/schoolCalendarSaveQueue.js`. Feed each successful response revision into the next `If-Match`; after 409/428 block followers and require reload. A header-less old backend remains temporarily compatible, but a new backend revision failure must not fall back to an unguarded retry.
- Do not introduce mojibake or placeholder `????` text.

## Anti-Patterns
- Do not let student `todayLocalKey()` semantics leak into admin selected-date flows.
- Do not hand-edit generated link maps when a script should regenerate them.
- Do not make broad changes to `student.js` without testing the student page surface.
- Do not replace shared helper behavior with one-off fetch wrappers.
- Do not reintroduce the retired seven-endpoint bootstrap fallback. A failed `/api/student/bootstrap` request must not render a partial page without assigned tests or authoritative review membership.
- Do not persist student review registration through `/api/updates/self-study` or invent review/training-pack update endpoints.
- Keep completed rows from today's named `source: "auto"` assignment in the current playlist with the blue completion badge, including after the class log is archived; do not duplicate them in the review chooser. Historical completed assignments may move to review, while a manually reopened green assignment must clear stale local completion and remain in today's playlist.
